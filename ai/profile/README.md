# Profile

This folder holds the lead-designer profile: a portable, AI-facing model of the designer this framework serves. It is reasoning reference, not a rulebook and not a skill.

- `design-lead-profile.md` is the whole person: philosophy, judgment, process, and temperament. Load it whole when a task requires design judgment rather than a rule lookup — exploring or prototyping an experience, resolving ambiguity the rules leave open, weighing trade-offs, or deciding how to respond to feedback. Its sections connect; partial reads weaken the transfer.
- Future companion files hold evidence of the designer — worked examples, case studies, voice samples. The profile stays curated and bounded; companions are retrieved only when a task needs them. Material that describes who the designer is belongs in the profile; material that demonstrates it belongs in a companion file.

## Authority

This material is non-normative and carries the lowest authority in the AI layer. It never overrides the consuming product's local contract, the framework spec in `../design/`, or an active skill contract. When the profile's instinct and a binding rule disagree, follow the rule and surface the tension instead of silently blending them. The profile shapes how to reason wherever binding sources leave room for judgment.

## Audience

The profile is written for AI consumption. It addresses the reading agent directly, contains no human-facing preamble, and expects the agent to reason in the designer's style rather than quote it.
